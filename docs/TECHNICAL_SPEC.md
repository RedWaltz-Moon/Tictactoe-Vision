## 1. 系统边界

```
  ┌─────────────────────────────────────────────────────────┐
  │                       你的模块                           │
  │                                                          │
  │  USB摄像头 ─→ YOLOv8n ─→ OpenCV ─→ Minimax ─→ 串口      │
  │               棋盘定位    棋子识别    AI决策     输出     │
  │                                                          │
```

**职责：** 摄像头进，串口出。下位机（机械臂/电磁铁控制）不在范围内。

## 2. 串口通信协议

### 2.1 帧格式

```
┌────────┬────────┬──────────────────┬────────┐
│ 0xAA   │  CMD   │      DATA        │ 0xBB   │
│ 帧头   │ 命令字  │   数据(变长)      │ 帧尾   │
│ 1Byte  │ 1Byte  │   0~N Byte       │ 1Byte  │
└────────┴────────┴──────────────────┴────────┘
```

### 2.2 交互指令 — 对局握手 (MCU ↔ 视觉)

| CMD | 名称 | 方向 | DATA | 示例帧 (hex) | 说明 |
|-----|------|------|------|-------------|------|
| `0x02` | GAME_START | MCU→视觉 | 无 | `AA 02 BB` | ① 新游戏开局，复位棋盘状态 |
| `0x05` | WHO_FIRST | MCU→视觉 | `0x00`=AI / `0x01`=人 | `AA 05 00 BB` / `AA 05 01 BB` | ② 指定先手方，游戏正式开始 |
| `0x10` | AI_MOVE | 视觉→MCU | `idx` `Xh` `Xl` `Yh` `Yl` | `AA 10 04 00 4B 00 4B BB` | ③ AI落子。例: idx=4, X=75mm, Y=75mm |
| `0x01` | PLAYER_DONE | MCU→视觉 | 无 | `AA 01 BB` | ④ 玩家落子完毕，机械臂归位，视觉自动检测棋盘 |
| `0x14` | GAME_OVER | 视觉→MCU | `0`=AI胜 `1`=人胜 `2`=平 | `AA 14 00 BB` / `AA 14 01 BB` / `AA 14 02 BB` | ⑤ 对局结果 |

### 2.3 内部指令

| CMD | 名称 | 方向 | DATA | 示例帧 (hex) | 说明 |
|-----|------|------|------|-------------|------|
| `0x03` | RESET | MCU→视觉 | 无 | `AA 03 BB` | 软复位，清空棋盘/状态 |
| `0x13` | THINKING | 视觉→MCU | 无 | `AA 13 BB` | 处理中，MCU 收到指令时的回复 |

### 2.4 交互时序 — AI先手

```
MCU                              视觉
 │                                  │
 │  上电                             │  初始化
 │                                  │
 │  → GAME_START                    │  ① 复位棋盘
 │  → WHO_FIRST(AI)                │  ② AI先手
 │                                  │  拍照检测(空盘) → AI计算
 │                      AI_MOVE ←   │  ③ AI第一步
 │                                  │  等待人走
 │  (机械臂放子, 人下棋)             │
 │  → PLAYER_DONE                   │  ④ 触发检测
 │                      THINKING ←  │  
 │                                  │  拍照 → 识别 → AI计算
 │                      AI_MOVE ←   │  ③ AI走
 │                                  │  等待人走
 │         ...循环 ④③...            │
 │                      GAME_OVER ← │  ⑤ 终局
 │                                  │  回到 IDLE
```

```
MCU                              视觉
 │                                  │
 │  上电                             │  初始化
 │                                  │
 │  → GAME_START                    │  ① 复位棋盘

 │                                  │  等待人走
 │  (人下棋, 机械臂放子)             │
 │  → PLAYER_DONE                   │  ④ 触发检测
 │                      THINKING ←  │  
 │                                  │  拍照 → 识别 → AI计算
 │                      AI_MOVE ←   │  ③ AI走
 │                                  │  等待人走
 │         ...循环 ④③...            │
 │                      GAME_OVER ← │  ⑤ 终局

```

### 2.6 时序差异对比

| 阶段 | AI先手 | 人先手 |
|------|--------|--------|
| 开局 | GAME_START→WHO_FIRST(AI)→自动检测→AI_MOVE | GAME_START→WHO_FIRST(人)→等待 |
| 第一步 | AI 直接检测空盘后走第一步 | 等人走完 PLAYER_DONE |
| 回合 | PLAYER_DONE→自动检测→AI_MOVE | PLAYER_DONE→自动检测→AI_MOVE |
| 终局 | GAME_OVER → IDLE | GAME_OVER → IDLE |

## 3. 坐标体系

### 3.1 棋盘索引编号

```
┌─────┬─────┬─────┐
│  0  │  1  │  2  │
├─────┼─────┼─────┤
│  3  │  4  │  5  │
├─────┼─────┼─────┤
│  6  │  7  │  8  │
└─────┴─────┴─────┘
```

### 3.2 物理坐标

棋盘左上角为原点，X轴右，Y轴下：

```
格子中心物理坐标 = ( (col + 0.5) × 30, (row + 0.5) × 30 )  单位: mm
```

### 3.3 像素 → 物理映射

- **输入：** YOLO 检测到 4 个角点的像素坐标
- **已知：** 4 个角点的物理坐标 `[(0,0), (W,0), (0,H), (W,H)]`
- **计算：** 仿射变换矩阵 → 任意像素映射到物理坐标

## 4. 视觉检测流水线

```
帧输入 → YOLO检测棋盘角点 → 旋转校正 → 裁切正方形 → 9格切分
                                                  ↓
         状态数组(0/1/2) ← 逻辑校验 ← 黑白分类 ← 每格HSV-V通道均值
```

### 4.1 棋盘定位 (YOLOv8n)

- 标注棋盘外框 + 4个角点 (keypoint)
- 训练数据：俯拍、0°~45°旋转、不同光照、不同棋子状态，**100+ 张**
- 置信度阈值：`0.5`
- 连续 3 帧低于阈值 → `ERROR(0)` 棋盘未找到
- 角点做**滑动平均**（窗口=3帧）平滑抖动

### 4.2 旋转校正

> 💡 固定俯拍无透视畸变，用**旋转变换**替代原始方案的透视变换，更简单稳定。

```
YOLO角点 → 计算旋转角度 → cv2.warpAffine 旋正 → 裁切正方形
```

### 4.3 棋子识别 (HSV + 自适应阈值)

**与 v1.0 方案的关键区别：不使用固定灰度阈值 127。**

| 步骤 | 方法 | 原因 |
|------|------|------|
| 颜色空间 | RGB → HSV，取 **V 通道** | 对金属反光更鲁棒 |
| 采样区域 | 仅取格子**中心 60%** 区域 | 抗边缘干扰 + 抗反光 |
| 参考锚点 | 从棋盘已知空白格采样 **baseline_V** | 阈值跟随环境亮度自适应 |
| 判空 | `|V_center - baseline_V| < baseline_V × 0.15` | 接近背景即为空 |
| 判黑 | `V_center < baseline_V × 0.6` | 显著暗于背景 |
| 判白 | `V_center > baseline_V × 1.2` | 显著亮于背景 |
| 辅助验证 | 圆形度 `4π × 面积 / 周长²` | 过滤手指等非圆形干扰 |

**对比：**

```
❌ 固定阈值 127:
   光照暗 → 白子 V=90  → 误判为黑
   光照亮 → 黑子 V=140 → 误判为白

✅ 相对比较:
   黑子 V ≈ baseline_V × 0.3~0.5
   白子 V ≈ baseline_V × 1.2~1.5
   空白 V ≈ baseline_V × 0.9~1.1
```

### 4.4 逻辑校验 (3条硬约束)

利用井字棋规则天然约束过滤误识别：

| 规则 | 内容 | 违反时处理 |
|------|------|------------|
| 规则1 | 每帧最多多 1 个棋子 | 重采 |
| 规则2 | 已有棋子不能消失或变色 | 重采 |
| 规则3 | 新棋子颜色必须符合黑白交替顺序 | 重采 |

> 连续 3 次校验失败 → `ERROR(2)` 识别异常

### 4.5 鲁棒性增强

| 场景 | 策略 |
|------|------|
| 连续 N 帧检测失败 | `ERROR(0)` 棋盘未找到 |
| 角点偏移超过阈值（相对上一帧） | 丢弃当前帧，使用缓存位置 |
| 棋盘面积变化 > 20% | 认为棋盘被移动，重新定位 |
| 机械臂执行期间 | 暂停图像采集 |

## 5. AI决策 (Minimax + Alpha-Beta 剪枝)

### 5.1 开局策略

- 空盘开局：**80%** 概率走索引 4 (中心)，**20%** 随机走角落 (0/2/6/8)
- 增加趣味性，避免 AI 永远走中心

### 5.2 算法伪代码

```python
def ai_move(board, ai_piece):
    # 1. 首步随机化
    if board_is_empty(board):
        return random_choice([4,4,4,4, 0,2,6,8])  # 80%中心 / 20%角

    # 2. 立即胜利：能赢直接赢
    for i in range(9):
        if board[i] == 0 and would_win(board, i, ai_piece):
            return i

    # 3. 立即防守：对手要赢赶紧堵
    opp = 2 if ai_piece == 1 else 1
    for i in range(9):
        if board[i] == 0 and would_win(board, i, opp):
            return i

    # 4. Alpha-Beta Minimax
    best_score = -inf
    for i in range(9):
        if board[i] == 0:
            board[i] = ai_piece
            score = minimax(board, 0, False, ai_piece, -inf, +inf)
            board[i] = 0
            if score > best_score:
                best_score, best_move = score, i
    return best_move
```

- 搜索空间 ≈ 9! = 362,880
- Alpha-Beta 剪枝后**毫秒级**完成

## 9. 关键设计决策

| 决策项 | 理由 |
|--------|------|
| **旋转校正** 替代 透视变换 | 固定俯拍无透视畸变，旋转更简单稳定 |
| **HSV-V通道 + baseline自适应** 替代 固定灰度阈值127 | 光照变化下固定阈值易失效，自适应阈值跟随环境亮度 |
| 仅取格子**中心60%**区域计算 | 抗边缘干扰 + 抗金属反光 |
| MOVE 同时传**索引+物理坐标** | 冗余设计：索引便于调试，坐标供下位机直接使用 |
| **逻辑校验层**：规则约束过滤误识别 | 大幅降低反光/遮挡导致的误判，利用井字棋规则特性 |
| 串口**外部触发**而非连续轮询 | 避免拍到机械臂运动画面，避免无效推理浪费算力 |
| **YOLOv8n**（不变） | 轻量、成熟、转换链路清晰，固定俯拍下Nano版足够 |
| **纯YOLO定位**（不加ArUco） | 支持0°~45°旋转，标注数据覆盖该范围即可 |
